# Trips as data — architecture

The app currently ships one trip (Northern Vietnam) whose shape leaks into the code, and a
`data/*.json` snapshot that nothing reads at runtime. This proposes one portable unit — the
**trip bundle** — as the thing the backend, the disk and the browser all speak.

## The unit: a trip bundle

```jsonc
{
  "schema": "nomad.trip.bundle.v1",
  "trip_id": "vietnam-2026",          // local identity; the server assigns its own record id
  "exported_at": "2026-10-25T…",
  "trip":   { …row shape of `trips` }, // name, title, start_date, end_date, travellers, currency, budget…
  "docs":   { "itinerary": […], "accommodation": […], "expenses": {…}, "packing": {…},
              "recommendations": […], "decisions": […], "travellers": {…} }
}
```

Generated by `tools/bundle_trip.py` from the existing `data/*.json`:

```
python3 tools/bundle_trip.py --id vietnam-2026   →  data/trips/vietnam-2026.json  (183 KB)
```

That file *is* the Vietnam trip. A second trip is a second file — no code change.

## Where the three copies live

| Copy | Store | Written by | Read by |
| --- | --- | --- | --- |
| Source of truth | PocketBase `trips` + one `trip_docs` row per section | `TripAuth.createTrip` / `saveDocs` (exists) | `openTrip` (exists) |
| Local file | `data/trips/<id>.json` (user-chosen path for export) | "Export trip" (new), `tools/bundle_trip.py` (now) | "Import trip" (new) |
| Offline cache | `localStorage["nomad.trip.bundle.v1.<tripId>"]` | `openTrip` on every successful load (new) | boot + offline fallback (new) |

## Staged change list

**Stage 1 — bundle on disk (done)**
`tools/bundle_trip.py` + `data/trips/vietnam-2026.json`. Nothing in the app changes.

**Stage 2 — bundle through the adapter** (`backends/pocketbase-adapter.js`, no UI change)
1. In `openTrip()` (`:452`) after `docs` is assembled: `cacheBundle(key, {trip, docs})`.
2. New `importBundle(bundle)`: `trips.create` from `bundle.trip`, then `saveDocs` per section,
   then cache and return the new id — one call turns a file into a trip.
3. New `exportBundle(tripId)`: read the cached bundle, or rebuild it from the DB rows.
4. Boot fallback in `app.js` around the `selectTrip` path (`:892`): if `TripAuth` is
   unconfigured or `openTrip` rejects, load the cached bundle and set `STATE.docs` from it,
   marking the app read-only-offline. Writes go to `localStorage["nomad.trip.outbox.v1.<id>"]`
   and replay on the next successful boot.
5. `auth.js` passthrough additions mirroring `TripAuth` (`:159`) — the file only forwards calls.

**Stage 3 — remove the Vietnam-shaped assumptions** (`app.js`)
1. `VND_PER_SGD` (`:87`) and `parseVndCostToSgd` (`:88`) → per-trip
   `trip.currencies = { primary: "SGD", local: { code: "VND", perPrimary: 20285 } }`;
   conversion reads the trip, and a trip without a local currency simply has no conversion.
2. Recommendation area filter (`STATE.recLocation`, `:41`) is the literal
   `['all','Hanoi','Ha Giang','Ninh Binh']` — derive the pills from the trip's `bases` plus the
   distinct locations in `docs.recommendations`.
3. The idea-swap logic (~`:200-300`) matches Vietnamese attraction strings in `if/else` chains.
   That belongs in data: `recommendations[].swap` describing the target day/item, or an AI call
   with the day as context. Per-trip, not per-deployment.
4. `NIGHT_GROUPS` (`:3033`) and any other literal lists keyed to this itinerary move into the
   accommodation document.

**Stage 4 — creating a trip from generated content**
`TripAuth.createTrip` already exists; `importBundle` makes "AI generated an itinerary → bundle →
trip" a single call. The generator just has to emit the bundle schema.

## Why a bundle and not six endpoints

- One atomic artefact: export, import, cache, diff and seed all use the same shape, so the
  offline path can never drift from the server path.
- `trip_docs` stays exactly as it is (one row per section), so no migration of existing trips.
- A bundle is small enough for `localStorage` (183 KB for the richest trip here) — no IndexedDB,
  no service-worker cache invalidation.

## Known gaps (deliberately not addressed here)

- No conflict resolution: last write wins, and the offline outbox replays blindly.
- Photos are not in the bundle; card images are fetched per render from Wikipedia.
- `expenses.json` and `itinerary.json` disagree on totals (S$978 vs S$883) and on per-day
  bucketing. The bundle carries both verbatim; reconciling them is a data decision, not a
  schema one.
